# Puzzle 896: Shortest strings containing all small primes as subsequences

> **In short:** The page asks for the shortest digit strings that contain every word of a set as a subsequence: 36 digits for set A (ten 10-digit numbers), 11 for the primes below 100 and 21 for the primes below 1000; only the last two were called best. (1) A SAT solver proves 10 and 20 digits impossible for the two prime sets. (2) For A, a search over position vectors with a pairwise-supersequence bound proves 35 digits impossible, and a breadth-first search confirms it. So 36, 11 and 21 are all optimal.

**Puzzle:** [primepuzzles.net](https://www.primepuzzles.net/puzzles/puzz_896.htm)

**Status:** answered · all three optimal: set A 36 (exhaustive search, two methods), sets B and C 11 and 21 (SAT in both directions, two solvers agree)

## The question

Given a set of numbers, find the shortest string S of decimal digits that contains every number as a subsequence (digits in order, not necessarily adjacent).

- **Q1.** An algorithm.
- **Q2.** Best strings for set A (ten given 10-digit numbers), set B (primes 2 … 97) and set C (primes 2 … 997).

## How we found it

Whether a fixed word w is a subsequence of S is a dynamic programme along S: "the first j digits of w occur in the first i positions of S". Writing that table as Boolean variables turns the whole question, for a fixed length L, into a SAT instance. Words that share a prefix share the same table rows, so the formula for all 168 primes below 1000 stays small.

## The math

**Step 1 (proved). The formula.** Variables x(i, d): position i of S holds digit d, exactly one per position. For each prefix u = w₁…w_j of a word and each i ≤ L, a variable m(u, i) with m(u, i) ⇔ m(u, i−1) ∨ (m(u⁻, i−1) ∧ x(i, w_j)), where u⁻ is u without its last digit, m(∅, i) is true and m(u, 0) false for u ≠ ∅. Then m(w, L) holds exactly when w is a subsequence of S. Asserting m(w, L) for every word gives a formula that is satisfiable iff a string of length L exists.

**Step 2 (computed).** CaDiCaL finds 24817536197 for set B and 468593219728563041973 for set C. It proves the formulas for length 10 (set B) and length 20 (set C, about 2 minutes) unsatisfiable. So 11 and 21 are optimal.

**Step 3 (proved). A simple lower bound.** S must contain each digit d at least as often as the word with the most d's. For the primes below 10⁵ this gives 3 zeros (10007), four each of 1, 2, 3, 4, 7, 8, 9 (e.g. 10111, 22229, 23333, 44449, 47777, 88883, 49999), and three each of 5 and 6, since no prime below 10⁵ has four 5s or four 6s. That is 37, against the 40 on the page. For set A the same bound is only 26.

**Step 4 (computed). Set A: 36 is optimal.** Work with the vector (p_1, …, p_10) of how many digits of each word are already matched. Appending a digit d advances every word whose next digit is d. Greedy matching is optimal for subsequences, and a digit that advances no word can be deleted, so only the next digits of the words need to be tried. Two lower bounds on the remaining length hold for every state:

- the largest shortest common supersequence of two remaining suffixes (45 small tables);
- the sum over digits d of the largest remaining number of d's in one word.

A depth-first search with bound "steps + bound ≤ 35" and a table of states already expanded at an earlier or equal depth ([code/p896_scs_bb.c](code/p896_scs_bb.c)) visits 72 million nodes in 21 s and finds no string. A second program ([code/p896_scs_bfs.c](code/p896_scs_bfs.c)) builds every layer of states reachable with t digits, deduplicated, keeping only states with t + (digit-count bound) ≤ 35. The largest layer has 1.68 million states, layer 35 is empty, and with 36 digits the final state is reached. The two programs share no code and use different bounds; both agree that 35 is impossible. Kamenetsky's 36-digit string is therefore optimal; the search also finds 435458761982386452075700064095273819.

**What this does not settle.** The primes below 10⁵ (between 37 and 40); the page did not ask for them.
