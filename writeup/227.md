# Puzzle 227: Powers whose integer parts are all prime

> **In short:** We found a number t (a little above 3001) for which the integer part of t, t², t³, … is prime for the first 239 powers in a row. The longest chain known before had 100 powers.

**Puzzle:** [primepuzzles.net](https://www.primepuzzles.net/puzzles/puzz_227.htm)

**Status:** beaten · PRP (probable primes)

## The question

Crandall and Pomerance (*Prime Numbers, a Computational Perspective*, research problem 1.75) note that for t = 1287/545 the integer parts of t, t², …, t⁸ are 2, 5, 13, 31, 73, 173, 409, 967, all prime. The puzzle asks for a longer chain: a t whose first j powers all have a prime integer part, for j as large as possible.

## Current record vs ours

| | Chain | Length |
|---|---|---|
| On the page (P. Carmody, 2004) | explicit t listed on the page | 37 powers |
| Best known (D. Terr, Problem 42) | referenced from the page | 100 powers |
| **Ours** | t = a / 2²⁷⁶⁰ with ⌊t⌋ = 3001 (a in [data/227.txt](data/227.txt)) | **239 powers** |

## How we found it

Stinchcombe already describes the method on the page: each new prime only narrows the range where t can lie. If ⌊t⌋ = p₁, then p₁ ≤ t < p₁ + 1. Squaring, t² lies in an interval that contains several primes; pick one, p₂, and now t is pinned to a smaller interval. Repeat. The chain only stops when an interval contains no prime at all.

Two choices let us go much further than earlier attempts:

- **Start large.** Near t ≈ 3000 the interval for tᵏ is wide enough that it usually still contains a prime long past k = 100: the expected number of choices per step is about t / (k·ln t).
- **Back up instead of stopping.** When step k has no prime left, we go back and choose a different prime at an earlier step (depth-first search with backtracking).

At the end any number inside the final interval works as t. We picked a fraction with a power-of-2 denominator so the check is exact integer arithmetic.

## The math

The chain is a sequence of nested intervals. After choosing primes p₁, …, p_k:

```
p_j ≤ t^j < p_j + 1        for every j ≤ k
⇔  p_j^(1/j) ≤ t < (p_j + 1)^(1/j)
t ∈ I_k = ⋂_{j ≤ k} [ p_j^(1/j), (p_j + 1)^(1/j) )
```

Step k + 1 needs a prime p in the interval

```
[ (min I_k)^(k+1), (max I_k)^(k+1) )
```

and then I_{k+1} = I_k ∩ [ p^(1/(k+1)), (p + 1)^(1/(k+1)) ). The width of I_k shrinks fast, but t^(k+1) also grows, and for t ≈ 3000 the window for t^(k+1) keeps containing primes for a long time.

Our final t is exact:

```
t = a / 2^2760,   a has 835 digits,   ⌊t⌋ = 3001
⌊t^j⌋ = ⌊a^j / 2^(2760·j)⌋  is prime for j = 1, …, 239,   composite for j = 240
```

## The numbers

The first few integer parts are 3001, then primes near 3001², 3001³, …; the 239th has 832 digits. The full value of a is in [data/227.txt](data/227.txt).

All 239 integer parts pass the BPSW test plus 10 Miller-Rabin rounds: they are probable primes, not proven ones.

## Verify it yourself

This script reads a from the data file, computes the integer part of every power t^j exactly, and checks that the first 239 are probable primes. It takes about a minute.

```python
import gmpy2

# read t = a / 2^E from the data file
vals = {}
for line in open("writeup/data/227.txt"):
    if "=" in line and not line.startswith("#"):
        key, value = line.split("=")
        vals[key.strip()] = int(value)
a, E = gmpy2.mpz(vals["a"]), vals["E"]

assert (a >> E) == 3001                      # the integer part of t itself is 3001

power = gmpy2.mpz(1)
for j in range(1, 240):
    power *= a                               # power = a^j
    floor_tj = power >> (E * j)              # floor(t^j) = floor(a^j / 2^(E*j)), exact
    assert gmpy2.is_prime(floor_tj, 10), j   # the integer part of t^j is a probable prime

print("floor(t^j) is a probable prime for every j = 1..239")
```

Run it from the repository root, so the relative path `writeup/data/227.txt` resolves.
