# Puzzle 597: The long race of primes and semiprimes

> **In short:** The record quadratic for the long race, x² + x + 247757, had 9567 prime or semiprime values for x = 0 … 10,000. The construction: (1) shift it to (x − 5000)² + (x − 5000) + 247757; (2) this keeps its prime-friendly residues; (3) its largest values drop from about 10⁸ to about 2.5·10⁷. This gives x² − 9999x + 25242757 with 9743 hits, beating 9567.

**Puzzle:** [primepuzzles.net](https://www.primepuzzles.net/puzzles/puzz_597.htm)

**Status:** beaten (Q2)

## The question

For a quadratic f(x) = Ax² + Bx + C, count how many of the values f(0), f(1), …, f(N) are a prime or a semiprime (a product of exactly two primes). Question 2, "the long race", asks for the best f for N = 10,000.

## Current record vs ours

| | Polynomial | Hits for x = 0 … 10,000 |
|---|---|---|
| Current record (E. Vantieghem) | x² + x + 247757 | 9567 |
| **Ours** | x² − 9999x + 25242757 | **9743** |

## How we found it

The record polynomial x² + x + 247757 is a classic prime-rich quadratic, but on the track 0 … 10,000 its values grow from about 250,000 to about 100 million. Large numbers are less often prime or semiprime.

The polynomial does not care where its middle is. So we shifted it so that its lowest point sits at x = 5000, the middle of the track. The values now run from about 250,000 up to only about 25 million on both sides, four times smaller than before, and the hit count goes up. Rivera himself uses such shifted forms (like 2x² − 94x + 54193) on the same page.

One side effect: the shifted polynomial is symmetric around 4999.5, so x and 9999 − x give the same value. The puzzle counts values f(x) for each x, so this is within the rules, but it means there are only 5001 different values.

## The math

```
f(x) = (x − 5000)² + (x − 5000) + 247757
     = x² − 9999x + 25242757
```

The same prime-friendly structure is kept (no prime below 41 ever divides x² + x + 247757), while the size drops:

```
x² + x + 247757,        x = 0…10000:   values up to ≈ 1.0·10^8
x² − 9999x + 25242757,  x = 0…10000:   values up to ≈ 2.5·10^7
```

Roughly, a number of size n is prime or semiprime with probability that falls slowly as n grows, so making every value about 4 times smaller raises the count.

## The numbers

```
listed record:  x² + x + 247757          9567 hits out of 10001
ours:           x² − 9999x + 25242757    9743 hits out of 10001
```

## Validation

This script counts, for both polynomials, how many values for x = 0 … 10,000 are a prime or a semiprime. It takes about half a minute.

```python
import numpy as np

def prime_table(limit):
    # is_prime[n] for 0 <= n <= limit (sieve of Eratosthenes)
    s = np.ones(limit + 1, dtype=bool)
    s[:2] = False
    for i in range(2, int(limit ** 0.5) + 1):
        if s[i]:
            s[i * i::i] = False
    return s

is_prime = prime_table(101_000_000)                # covers every value below
small_primes = np.flatnonzero(is_prime[:11000])    # enough to find a factor of any value <= 1.21e8

def prime_or_semiprime(v):
    if is_prime[v]:
        return True
    for p in small_primes:                         # smallest prime factor p ...
        if v % p == 0:
            return bool(is_prime[v // p])          # ... semiprime if the cofactor is prime
    return False

def hits(f):
    return sum(prime_or_semiprime(f(x)) for x in range(10001))

old = hits(lambda x: x * x + x + 247757)
new = hits(lambda x: x * x - 9999 * x + 25242757)
assert old == 9567 and new == 9743
print("listed:", old, " ours:", new)
```
