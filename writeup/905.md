# Puzzle 905: Primes from a recursive formula

> **In short:** The record was 19 different primes in a row from a recursion f(m) = P(f(m − 1)); P(x) = x + d is forbidden. The construction: (1) take PrimeGrid's 27 primes in arithmetic progression; (2) add to x + d a multiple of a product that vanishes at the first 26, giving degree 26; (3) choose the multiple to make one more value prime. This gives 28 primes, the last a PRP.

**Puzzle:** [primepuzzles.net](https://www.primepuzzles.net/puzzles/puzz_905.htm)

**Status:** beaten (within the stated rules) · PRP (the 28th prime is a probable prime)

## The question

Choose a polynomial P and a start k, and set f(0) = k, f(m) = P(f(m − 1)). How many different primes in a row can f produce? Example from the page: f(n) = 3·f(n−1) − 574 with f(0) = 307 gives 13 primes (307, 347, 467, 827, …).

The page forbids one trivial trick: a **linear** P(x) = x + d with leading coefficient 1, because that just walks along a known arithmetic progression of primes. Any other polynomial is allowed.

## Current record vs ours

| | Formula | Primes in a row |
|---|---|---|
| Current record (J. K. Andersen, 2017) | f(n) = 2·f(n−1) − 1 on a Cunningham chain of length 19 | 19 |
| **Ours** | degree-26 polynomial through the PrimeGrid AP-27 (below) | **28** |

## How we found it

The longest known run of primes in arithmetic progression is PrimeGrid's AP-27: a₀, a₀ + d, …, a₀ + 26d, all prime. The rule P(x) = x + d is forbidden, but any polynomial that **agrees with x + d at those 26 points** walks along the same primes. So we added a multiple of (x − a₀)(x − a₁)…(x − a₂₅), which is zero at exactly those points and changes nothing there:

```
P(x) = x + d + c · (x − a₀)(x − a₁)···(x − a₂₅)
```

This P has degree 26, so it is not the forbidden linear rule. It gives a₀ → a₁ → … → a₂₆ (27 primes), and then one more step jumps to a huge new number, which we made prime by choosing the constant c. c = 18 is the first that works, giving a 28th prime with 451 digits.

## The math

With aᵢ = a₀ + i·d for i = 0, …, 26:

```
P(aᵢ) = aᵢ + d = a_{i+1}        for i = 0, …, 25   (the product term vanishes)
P(a₂₆) = a₂₆ + d + c · ∏_{i=0..25} (a₂₆ − aᵢ)
       = a₂₇ + c · ∏_{i=0..25} (26 − i)·d
       = a₂₇ + c · 26! · d^26
```

where a₂₇ = a₀ + 27d. So f(27) = a₂₇ + c·26!·d²⁶, and with c = 18 this 451-digit number is a probable prime. All coefficients of P are whole numbers.

## The numbers

```
a₀ = 224584605939537911,   d = 81292139 · 223092870   (PrimeGrid AP-27, 2019; all terms below 2^64)
f(0..26) = a₀, a₀ + d, …, a₀ + 26d                       (27 proven primes)
f(27)   = a₀ + 27d + 18 · 26! · d^26                     (451 digits, probable prime)
```

## Validation

This script builds the progression, checks that P sends each term to the next, and tests the 28th value. The first 27 primes are below 2⁶⁴, where the test is exact; the 28th passes BPSW plus 25 Miller-Rabin rounds.

```python
import math
import gmpy2
from sympy import isprime

a0, d = 224584605939537911, 81292139 * 223092870
ap = [a0 + i * d for i in range(27)]                  # the PrimeGrid AP-27
assert all(isprime(t) for t in ap)                    # 27 primes (exact below 2^64)

c = 18
def P(x):
    # degree-26 polynomial: x + d plus c times a product that vanishes at a_0 .. a_25
    return x + d + c * math.prod(x - a for a in ap[:26])

f = [a0]
for _ in range(27):
    f.append(P(f[-1]))

assert f[:27] == ap                                   # P walks along the progression
assert f[27] == a0 + 27 * d + c * math.factorial(26) * d ** 26
assert len(str(f[27])) == 451
assert gmpy2.is_prime(f[27], 25)                      # the 28th value is a probable prime
assert len(set(f)) == 28                              # all 28 values are different

print("28 different primes in a row from a degree-26 recursive polynomial")
```
