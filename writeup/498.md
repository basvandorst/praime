# Puzzle 498: p·s + q·r is never a square

> **In short:** The page claims that p·s + q·r is never a square for four consecutive primes p < q < r < s; no counterexample is known, and a later search of the three forms pq + rs, ps + qr, pr + qs to 40 digits found only 203233 for pq + rs. (1) With half-gaps a < b < d the square condition is U² − 8z² = t² − 8ab, U = 2p + t, t = a + b + d. (2) Its solutions are orbits of finitely many fundamental ones; walking them to 100 digits for all gap triples gives 3.1·10⁹ candidates. (3) One is a counterexample: a proved 77-digit prime p with gaps 274, 300, 324. (4) The same run gives a second pq + rs, of 58 digits.

**Puzzle:** [primepuzzles.net](https://www.primepuzzles.net/puzzles/puzz_498.htm)

**Status:** disproved (counterexample: p = 11676583373868016849349945425661876543184231432061070831984678948459667093277, q = p + 274, r = p + 300, s = p + 324, proved consecutive primes, ps + qr a square) · see also [655](655.md)

## The question

Sebastian Martin Ruiz: for four consecutive primes p < q < r < s, "p·s + q·r has a square free prime factor. Then p·s + q·r is never a square. Is it true?" Enoch Haga and Farideh Firoozbakht give squares of the other forms (203233·203249 + 203279·203293 = 287458²) and expect solutions to exist; Carlos Rivera lists near misses and the form 2p² + p(a + b + d) + ab = m². On [puzzle 655](https://www.primepuzzles.net/puzzles/puzz_655.htm) Jan van Delden sieved the three forms to p < 4000·2³² and solved the Pell-type equation for gap triples with s − p ≤ 500 up to about 40 digits: no solution besides 203233.

## How we found it

Page 655 already has the reduction to a Pell-type equation. The expected number of solutions grows only like ln ln p (step 5), so the search has to reach far beyond 40 digits and wider gaps; that needs a fast way to discard candidates. [`code/p655_pell.py`](code/p655_pell.py) lists the fundamental solutions for every right-hand side k once, carries every orbit modulo 3·5·…·23 and modulo 29·…·43 in numpy, pairs each orbit point with each gap triple of the same k, sieves p, q, r, s with these residues and builds exact integers only for the 1 % that survive. The run to 100 digits took 5 minutes on each of two cores, 350 MB each.

## The math

**Step 1 (proved). The equation.** Let q = p + 2a, r = p + 2b, s = p + 2d with half-gaps 0 < a < b < d, and t = a + b + d. Then

- pq + rs = 2p² + 2tp + 4bd, ps + qr = 2p² + 2tp + 4ab, pr + qs = 2p² + 2tp + 4ad,

so all three are N = 2p² + 2tp + 4C with C = bd, ab, ad. N is even, so a square N = y² has y = 2z and p² + tp + 2C = 2z². Then p(p + t) is even and p is odd, so t is odd. Multiplying by 4: (2p + t)² − t² + 8C = 8z², that is

- U² − 8z² = k, with U = 2p + t and k = t² − 8C.

**Step 2 (proved). Orbits.** If (U, z) solves U² − 8z² = k, so does (3U + 8z, U + 3z), because 3² − 8·1² = 1. Every solution lies in the orbit of a fundamental solution with 8z² ≤ k (k > 0) or 4z² ≤ |k| (k < 0) (Nagell's bounds for the unit 3 + √8). An orbit that starts with z < 0 can pass through U < 0; the script follows it with the sign changed and keeps the points on the way. Each step multiplies U by 3 + √8 = 5.83, so 133 steps reach 100 digits.

**Step 3 (computed). Completeness of the enumeration.** Without sieve and primality tests the script lists all integers p with N a square for a < b < d ≤ 12 and 3 ≤ p < 10⁷: 2793 solutions, the same set as a plain loop over p.

**Step 4 (computed). The search.** Range: p < 10¹⁰⁰, all triples with t odd, {0, 2a, 2b, 2d} not covering all classes mod 3, and d ≤ 7·log₁₀ p + 30, that is s − p ≤ 6.08 ln p + 60 (at most 730). There are 2241234 starting solutions for |k| ≤ 4796100 and about 3.1·10⁹ pairs (orbit point, triple); the sieve leaves 1 % for exact tests. Result: exactly three quadruples of consecutive primes,

- pq + rs: p = 203233 (gaps 16, 46, 60) and p = 1150284232069964804556646431054740232316097446258616188423 (gaps 484, 610, 660),
- ps + qr: p = 11676583373868016849349945425661876543184231432061070831984678948459667093277 (gaps 274, 300, 324),
- pr + qs: none.

For the 77-digit p: t = 449, k = 449² − 8·137·150 = 37201. A smaller solution of any type would need s − p > 6.08 ln p + 60; for three gaps of mean ln p this has probability below e^(−6.08)(1 + 6.08 + 6.08²/2) = 5.8 %, so the two new solutions are probably, not provably, the least.

**Step 5 (heuristic). Why so far out.** N ≈ 2p² is a square with probability 1/(2√N) = 1/(2√2·p), and primes have density 1/ln p, so the expected number of solutions of one type between P₁ and P₂ is ∫ dp/(2√2 p ln p) = 0.354·ln(ln P₂/ln P₁). From 4000·2³² to 10¹⁰⁰ this is 0.71 per type; we find 1, 1 and 0. [`code/p655_calib.py`](code/p655_calib.py) checks the model by counting near-squares N = m² + 5040j, |j| ≤ 500, for p ≤ 3·10⁹: 175, 146 and 153 against 144.4 expected (ratios 1.21, 1.01, 1.06). Each further solution costs a factor e^(1/0.354) = 17 in the number of digits.

**Step 6 (proved). The primes.** For each solution the next three primes after p were recomputed; p, q, r, s are proved prime with PARI's isprime, every number in between fails a probable-prime test, and N is a square by integer square root.
