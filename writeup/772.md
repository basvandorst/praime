# Puzzle 772: Neighbourhood sums that are primes

> **In short:** Fill an N × N grid A with distinct non-negative integers and let B hold, in each cell, the sum of A over the cell and its eight neighbours; all B values must be distinct. Q1 asks for the minimal sum of B with as many primes in B as possible. Q2 asks for as many primes as possible in A and B together, again with minimal sum of B. The best values on the page for N = 3 are sum 309 with all nine B values prime (Q1, after 304 with eight), and 17 primes with sum 546 (Q2). (1) Sum(B) = 4·(corners) + 6·(edges) + 9·(centre) + … is linear in A, and a prime B value (≥ 6) is odd. So the parity of A must solve a linear system mod 2, and an even A value can be prime only if it is 2. (2) The parity system bounds Q2: at most 17 primes for N = 3 and 29 for N = 4, the page's counts. (3) An exact search proves the minimal sums for N = 3: **291** with all nine B values prime (CP-SAT and an exhaustive Python search agree), and **514** with 17 primes (CP-SAT and HiGHS agree). Both beat the page, and both are optimal.

## The question

A is an N × N matrix of distinct non-negative integers. B(x) is the sum of A over x and its (up to 8) king neighbours, and all B values must be distinct as well.

- Q1: "minimal sum, maximal quantity of primes" in B, for N = 3, 4, 5, 6.
- Q2: maximal number of primes in A and B together, and minimal sum of B.

## The math

**Step 1 (proved): the sum.** Each A value is counted once in every B cell whose neighbourhood contains it: 4 times at a corner, 6 at an edge and 9 inside. So sum(B) = Σ w(x)·A(x) with these weights. Without primes, the least sum gives the smallest values to the largest weights (164, 630, 1728 for N = 3, 4, 5), and CP-SAT finds grids with distinct B that reach these bounds.

**Step 2 (proved): parity.** A B value is at least 0 + 1 + 2 + 3 = 6, so a prime B value is odd, and B(x) is odd iff an odd number of the A values around x are odd. An even A value is prime only if it equals 2. For a set E of even cells, at most (N² − |E|) + [E ≠ ∅] A values and at most #{x : |nbhd(x) \ E| odd} B values can be prime. Maximising over all 2^(N²) sets E gives **17** for N = 3 (E = {centre}: 9 + 8) and **29** for N = 4 (E = two diagonal inner cells: 15 + 14). The page reaches both counts, which are therefore maximal. For Q1 with all of B prime, the system "every neighbourhood holds an odd number of odd cells" has a unique solution for N = 3 (only the centre odd), for N = 4 (only the corners) and for N = 6; it has 512 solutions for N = 5.

**Step 3 (computed): the optimal sums for N = 3.**

- *Q1.* CP-SAT ([code/p772_q1_cpsat.py](code/p772_q1_cpsat.py)), with distinct A ≤ 100 and every B a distinct prime, proves 291 optimal in 10 s. The bound A ≤ 100 is no restriction, since every A value is at most 291/4.
  Independently, [code/p772_verify.py](code/p772_verify.py) enumerates every grid with an odd centre and eight distinct even values, under the weight bound 4·corners + 6·edges + 9·centre ≤ 291 (all permutations). It finds no grid with nine distinct prime B values and a smaller sum.
- *Q2.* The only parity configuration with 17 primes has the 2 in the centre and odd primes elsewhere. CP-SAT ([code/p772_q2_cpsat.py](code/p772_q2_cpsat.py)) proves 514 optimal. HiGHS solves the same problem as a 0/1 program (one binary per allowed value of each cell, distinctness per value) and also returns 514. Again the value bounds (A ≤ 514/4, B < 650) are no restriction.

**N = 4 (not improved).** With the parity pattern fixed and the page's grid as a hint, CP-SAT does not get below 988 (Q1) or 1728 (Q2) in a few minutes, and its lower bounds stay weak (under 400). These cases remain open.
