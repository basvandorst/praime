# Puzzle 1142: Why the Fridman–Grime constant produces every prime

> **In short:** The page asked why ⌊p(n)#·k − p(n)·⌊p(n−1)#·k − 1⌋⌋ with k = 2.920050977… gives every prime; nothing was posted. The proof: (1) k = Σ (p_m − 1)/p_(m−1)#; (2) p_n#·k = S_n + T_n with S_n − p_n·S_(n−1) = p_(n+1) − 1; (3) Bertrand's postulate gives 1 < T_n < 2. This proves the expression equals p_(n+1).

**Puzzle:** [primepuzzles.net](https://www.primepuzzles.net/puzzles/puzz_1142.htm)

**Status:** answered · proof (the argument of Fridman, Garbulsky, Glecer, Grime and Tron Florentin, Amer. Math. Monthly 2019, adapted to Rotondo's form)

## The question

Davide Rotondo's form of the prime-representing constant is

p(n+1) = ⌊p(n)#·k − p(n)·⌊p(n−1)#·k − 1⌋⌋,

with p(1) = 2 and k = 2.920050977316134…. Q asks why this works. The page has no contribution.

## The answer

**1. The constant.** k = Σ_(m≥1) (p_m − 1)/(p_1⋯p_(m−1)) = 1 + 2/2 + 4/6 + 6/30 + 10/210 + … = 2.920050977….

**2. Integer part and tail.** For each m ≤ n + 1, the term (p_m − 1)·p_n#/p_(m−1)# is an integer. Write

p_n#·k = S_n + T_n,   S_n = Σ_(m≤n+1) (p_m − 1)·p_n#/p_(m−1)#,   T_n = Σ_(j≥1) (p_(n+1+j) − 1)/(p_(n+1)⋯p_(n+j)).

**3. One term survives.** In p_n·S_(n−1), every term with m ≤ n appears exactly as in S_n. Only m = n + 1 is left over:

S_n − p_n·S_(n−1) = p_(n+1) − 1.

**4. The tail lies strictly between 1 and 2.** The tail satisfies T_n = (p_(n+2) − 1 + T_(n+1))/p_(n+1).

- Lower bound: p_(n+2) − 1 > p_(n+1), so already T_n > 1.
- Upper bound: Bertrand's postulate gives p_(n+2) ≤ 2p_(n+1) − 1, so T_n ≤ 2 + (T_(n+1) − 2)/p_(n+1). The terms of T_n decay geometrically, so S = sup T_n is finite. Then S ≤ 2 + (S − 2)/2, which gives S ≤ 2.
- Equality T_n = 2 would need equality in Bertrand at every later step, which never happens. So T_n < 2.

**5. Conclusion.** Since 1 < T_(n−1) < 2, we get ⌊p_(n−1)#·k − 1⌋ = S_(n−1). Therefore

⌊p_n#·k − p_n·S_(n−1)⌋ = ⌊S_n − p_n·S_(n−1) + T_n⌋ = ⌊p_(n+1) − 1 + T_n⌋ = p_(n+1).

This also explains point (b) on the page. k is defined from all the primes, so the formula recovers the primes instead of predicting them. Each step reads one more "digit" of k in the mixed-radix base given by the primes.

[`writeup/code/p1142_verify.py`](code/p1142_verify.py) computes k and the tails T_n as exact fractions. It checks 1 < T_n < 2 for n < 300, and that the formula gives p_(n+1) for 2 ≤ n < 300.

## Beyond the page: shorter constants

The page's recurrence is a special case of

f_(n+1) = ⌊f_n⌋ + R(⌊f_n⌋)·{f_n},   f_1 = 2 + Σ_(n≥1) g_n/(R(p_1)⋯R(p_n)),

where g_n = p_(n+1) − p_n and {·} is the fractional part. The recurrence gives ⌊f_n⌋ = p_n for every n whenever every gap satisfies g(p) ≤ R(p) − 1, because {f_n} = (g_n + {f_(n+1)})/R(p_n) < 1. The page's constant k is the case R(p) = p, which Bertrand's postulate allows. Every digit beyond the size of the gap is wasted, and proven gap bounds allow a much smaller radix:

R(p) = ⌊ln² p⌋ + 4 for p < 4·10¹⁸,   R(p) = ⌊p/(25 ln² p)⌋ + 1 for p ≥ 4·10¹⁸.

**Why the gap condition holds for every prime:**
- **p ≤ 29.** Checked directly.
- **29 ≤ p < 4·10¹⁸.** Firoozbakht's conjecture is verified for all primes below 4·10¹⁸ ([Kourbatov 2015](https://arxiv.org/abs/1503.01744)). It implies p_(k+1) − p_k < ln² p_k − ln p_k − 1 for k > 9 ([Kourbatov, J. Integer Seq. 18 (2015)](https://arxiv.org/abs/1506.03042)), which is less than ⌊ln² p⌋ + 3.
- **p ≥ 396,738.** There is a prime in (x, x(1 + 1/(25 ln² x))] ([Dusart 2010, Prop. 6.8](https://arxiv.org/abs/1002.0442)).

So the constant is unconditional:

**f_1 = 2.371748647296557925430125190077989096689…**

The same recurrence on m = (p − 1)/2 also uses the fact that gaps between odd primes are even. Here u_(n+1) = ⌊u_n⌋ + R′(2⌊u_n⌋ + 1)·{u_n}, with R′(p) = ⌊ln² p/2⌋ + 3 (⌊p/(50 ln² p)⌋ + 1 from 4·10¹⁸ on), and p_n = 2⌊u_n⌋ + 1 from p_2 = 3 on:

**u_1 = 1.464022869260390485792096832101252997364…**

| Constant | 20 digits | 100 digits | 1,000 digits | Digits for the first 10⁶ primes |
|---|---|---|---|---|
| k = 2.920050977… (R = p, the page) | 16 primes | 53 primes | 350 primes | 6,722,808 |
| one bit per integer, Σ 2^(−p) | | | | 4,661,709 |
| f_1 = 2.371748647… (R = ⌊ln² p⌋ + 4) | 18 | 72 | 578 | 2,383,547 |
| u_1 = 1.464022869… (odd primes, half gaps) | 22 | 87 | 684 | 2,085,227 |

"d digits → N primes" means: truncate the constant to its first d significant digits, run the recurrence, and count the primes before the first wrong one. For the first 10⁶ primes, f_1 needs 2.82 times fewer digits than k, and u_1 3.22 times fewer. Both also need fewer than the prime constant Σ 2^(−p), which stores one bit for every integer. The ratio to k grows without bound, like ln p/(2 ln ln p).

Like k, these constants are built from the primes. They store the gaps more tightly; they do not predict anything. A radix rule cannot go below the information in the gaps, about log₁₀(e·ln p/2) digits per prime.
