# Puzzle 1251: Hundreds of prime cycles

> **In short:** The record was 72 cycles of p ↦ GPD(p + b), with b = 2358719. The construction: (1) write b + 1 = s₁·…·s_k in a circle; (2) then p_i + b = s_i·p_(i+1) for sums p_i built from the factors; (3) take b + 1 with many divisors. This gives 477 cycles below 10⁹ for b = 518918399; proven primes.

**Puzzle:** [primepuzzles.net](https://www.primepuzzles.net/puzzles/puzz_1251.htm)

**Status:** beaten (Q3) · proven primes

## The question

Take a prime p and replace it by the greatest prime divisor of a·p + b, written GPD(a·p + b). Repeat. Every starting prime eventually falls into a cycle. Question 3 asks which (a, b) give many different cycles, in a reasonable range (Vantieghem suggests below 10⁹).

## Current record vs ours

| | (a, b) | Cycles |
|---|---|---|
| Current record (G. Gusev) | (1, 2358719) | 72 |
| **Ours** | (1, 518918399) | **477** |

## How we found it

We first asked why Gusev's b = 2358719 works so well. The answer is in b + 1 = 2358720 = 2⁶·3⁴·5·7·13: a number with a lot of divisors.

Take a = 1 and write M = b + 1. If M = s·t, then the two primes s + 1 and t + 1 (when they are prime) form a cycle: (s + 1) + b = s + st = s·(t + 1), whose greatest prime factor is t + 1 (as long as s has no larger prime factor), and the same the other way round. More generally, every way of writing M as a product s₁·s₂·…·s_k read in a circle gives a cycle of length k, as long as certain numbers built from the factors are prime. So the more ways M splits into factors, the more cycles. We tried highly divisible values of M and took b + 1 = 2⁸·3⁴·5²·7·11·13.

## The math

Let M = b + 1 = s₁·s₂·…·s_k, read in a circle (after s_k comes s₁ again). Define

```
p_i = 1 + s_i + s_i·s_{i+1} + … + s_i·s_{i+1}·…·s_{i+k−2}
```

Then multiplying by s_i shifts the sum by one place:

```
s_i · p_{i+1} = s_i + s_i·s_{i+1} + … + s_i·…·s_{i+k−1} = (p_i − 1) + M = p_i + b
```

So p_i + b = s_i · p_{i+1}. If every p_i is prime and no prime factor of s_i is larger than p_{i+1}, the greatest prime factor of p_i + b is p_{i+1}, and going round the circle returns to p₁. For k = 2 this is the pair above: M = s·t gives p₁ = s + 1, p₂ = t + 1 and p₁ + b = s·(t + 1).

## Validation

This script reads each cycle from the data file, follows p → GPD(p + b) from its smallest element, and checks that it returns to the start after exactly the listed number of steps, that all cycles are different, and that everything stays below 10⁹.

```python
from collections import Counter
from sympy import factorint, isprime

b = 518918399
gpd = lambda n: max(factorint(n))                 # greatest prime divisor

cycles = [tuple(map(int, line.split())) for line in open("writeup/data/1251.txt")
          if line.strip() and not line.startswith("#")]
assert len(cycles) == 477

seen = set()
for start, length in cycles:
    assert isprime(start)
    orbit = [start]
    for _ in range(length):
        orbit.append(gpd(orbit[-1] + b))          # one step of the map
    assert orbit[-1] == start                     # back at the start after `length` steps
    assert len(set(orbit[:-1])) == length         # and not earlier
    assert min(orbit) == start and max(orbit) < 10**9
    seen.add(frozenset(orbit))

assert len(seen) == 477                           # all cycles are different
print("477 cycles; lengths:", sorted(Counter(l for _, l in cycles).items()))
```
