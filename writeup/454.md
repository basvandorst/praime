# Puzzle 454: How many primes n² + 1 are there below x?

> **In short:** The page asks whether √(2x)/ln x, √(2x)/(ln x − 1) and √(2/x)·Li(x) approximate π_q(x), the number of primes n² + 1 ≤ x, better than C·√x/ln x, and whether some x > 10²⁰ has √(2x)/ln x > π_q(x). (1) The refined Hardy–Littlewood count H(x) = (C/2)(Li(√x) − Li(√2)) matches all known counts up to 10²⁸. (2) The three formulas have the constant √2 = 1.414 instead of C = 1.373 and look better only where errors cancel. (3) Q2: yes, √(2x)/ln x overtakes H near 3.94·10³⁰ (heuristic).

**Puzzle:** [primepuzzles.net](https://www.primepuzzles.net/puzzles/puzz_454.htm)

**Status:** answered · heuristic (Hardy–Littlewood, calibrated on exact counts to 10²⁸)

## The question

π_q(x) counts the primes q ≤ x of the form n² + 1. Hardy and Littlewood conjectured π_q(x) ~ C·√x/ln x with C = 1.3728134628…; the page notes the refinement (C/2)∫₂ˣ du/(√u ln u).

1. Are a) √(2x)/ln x, b) √(2x)/(ln x − 1), c) √(2/x)·Li(x) better approximations than C·√x/ln x?
2. Is there an x > 10²⁰ with √(2x)/ln x > π_q(x)?

Enoch Haga answered Q1 with charts up to 10²⁰ (c beats b beats a). Q2 had no answer.

## Record vs ours

| | On the page | Ours |
|---|---|---|
| Q1 | charts to 10²⁰: c > b > a (holds only below about 10¹⁷; from 10²⁴ on a is best) | exact expansions: all three have the wrong constant (√2 instead of C); better than C√x/ln x only up to 2.3·10⁵⁹ (a), 9.7·10⁴⁴ (b), 7.0·10⁴⁴ (c), then 3.0157 % too high for ever |
| Q2 | open | **yes**: every x beyond about 3.95·10³⁰; none in [10²⁰, 3.92·10³⁰] (none at 10²⁰ … 10²⁸ by the published counts); first one within 0.07 % of 3.9383·10³⁰ |

## How we found it

Substituting u = t² turns the page's integral into a logarithmic integral of √x. Once everything is written as a series in 1/ln x, the four formulas differ only in their leading constant and their first correction term, and the comparison reads off directly. To make sure the Hardy–Littlewood formula itself can be trusted, we counted the primes n² + 1 exactly up to 10¹⁶ with a sieve over the classes n ≡ ±√−1 (mod q).

## The math

**Step 1: the refined formula is Li(√x)** (proved). With u = t², du/(√u ln u) = 2t dt/(t · 2 ln t) = dt/ln t, so

```
H(x) := (C/2) ∫₂ˣ du/(√u ln u) = (C/2) (Li(√x) − Li(√2)).
```

This is the Bateman–Horn prediction for f(n) = n² + 1: the expected count of n ≤ N with f(n) prime is C_f · Σ 1/ln f(n) ≈ C_f · (1/2) Li(N), with C_f = ∏_p (1 − w(p)/p)/(1 − 1/p). Here w(2) = 1 gives the factor 1 at p = 2. For odd p, w(p) = 1 + χ(p), where χ(p) = (−1/p), so the factor is 1 − χ(p)/(p − 1) and C_f = C.

**Step 2: C to 9 digits** (computed). The product ∏ (1 − χ(p)/(p − 1)) converges only conditionally (to 10⁷ it is still off by 2·10⁻⁵). Divide by ∏ (1 − χ(p)/p) = 1/L(1, χ) = 4/π:

```
C = (4/π) · ∏_{p ≡ 1 (4)} (1 − 1/(p − 1)²) · ∏_{p ≡ 3 (4)} (1 + 1/(p² − 1)),
```

which converges absolutely with tail O(1/P). Over odd p < 10⁷ it gives 1.372813463, the published value.

**Step 3: H is accurate** (computed exactly). A composite n² + 1 has a prime factor q ≤ n, and q | n² + 1 iff q = 2 or q ≡ 1 (mod 4) with n ≡ ±√−1 (mod q). Sieving those classes for n ≤ 10⁸ gives π_q(10ᵉ) for e = 1 … 16: 2, 4, 10, 19, 51, 112, 316, 841, 2378, 6656, 18822, 54110, 156081, 456362, 1339875, 3954181 (the published sequence A083844). At every one of these points, |H(x) − π_q(x)| < √π_q(x): the residuals divided by √π_q are −0.24, 0.15, −0.21, 0.40, −0.29, 0.94, 0.10, 0.50, −0.43, −0.56, −0.25, −0.60, 0.77, 0.06, 0.18, 0.52. OEIS A083844 continues the counts to 10²⁸ (a(17)–a(22) Gerbicz 2009, a(23)–a(25) Wolf and Gerbicz 2010, a(26)–a(28) Grantham 2017; not recomputed here). Their residuals are −0.16, 0.52, 0.26, −0.27, 0.12, −0.28, 0.17, −1.37, −1.04, −1.34, −0.03, −0.28. So H is right to within random-model noise all the way to 10²⁸, with no visible bias.

**Step 4: the four formulas as series** (proved). Li(y) = (y/ln y)(1 + 1/ln y + 2/ln² y + 6/ln³ y + …), and with y = √x, ln y = L/2 where L = ln x:

```
H     = C  · √x/L · (1 + 2/L + 8/L² + 48/L³ + …)
C√x/L = C  · √x/L
a     = √2 · √x/L
b     = √2 · √x/L · (1 + 1/L + 1/L² + …)
c     = √2 · Li(x)/√x = √2 · √x/L · (1 + 1/L + 2/L² + 6/L³ + …)
```

C√x/ln x has the right constant but misses the factor 1 + 2/L, which shrinks only like 1/ln x: still 4 % at 10²⁰. The other three have the constant √2 = 1.414214 instead of C = 1.372813, so their ratio to π_q tends to √2/C = 1.030157. They are always 3.0 % too high in the limit.

**Step 5: why a, b, c look better** (proved). In the reachable range the missing factor 1 + 2/L + … is about 1.03 to 1.11, and the wrong constant √2/C = 1.0302 cancels part of it. For c the first-order terms cancel exactly when √2(1 + 1/L) = C(1 + 2/L), i.e. L = (2C − √2)/(√2 − C) = 32.2, x ≈ 10¹⁴. That is why c is so good on Haga's charts (−0.13 % at 10¹⁶ in our table). Comparing |f/H − 1| with |C√x/(L·H) − 1| numerically:

| formula | better than C√x/ln x for | limit of f/π_q |
|---|---|---|
| a = √(2x)/ln x | 10²⁰ ≤ x < 2.34·10⁵⁹ | 1.030157 |
| b = √(2x)/(ln x − 1) | 10²⁰ ≤ x < 9.74·10⁴⁴ | 1.030157 |
| c = √(2/x)·Li(x) | 10²⁰ ≤ x < 7.00·10⁴⁴ | 1.030157 |

The ranking among a, b, c also changes with x, which the published counts show directly (relative errors at 10¹⁶, 10²⁰, 10²⁴, 10²⁸): a −2.92, −1.69, −0.87, −0.29 %; b −0.21, +0.50, +0.96, +1.28 %; c −0.13, +0.55, +1.00, +1.31 %. c is best only up to about 10¹⁷; b and c then overshoot (their extra 1/L term on top of the too-large constant), and from 10²⁴ on a is the best of the three. Haga's order c > b > a holds only below about 10¹⁷.

So the answer to Q1 is "yes in every range anyone can compute, no asymptotically": the improvement is a coincidence of constants, not a better formula. H itself (or Li(√x) times C/2) is the right one.

**Step 6: Q2** (heuristic, calibrated). Since a/H = (√2/C)·(C√x/L)/H and the bracket in step 4 decreases, a/H increases (checked on a grid of ln x from 46 to 546; at the end it is 1.02637, below the limit 1.030157). It crosses 1 once, at

```
x* = 3.938288 · 10³⁰.
```

Below x*, a < H. At x = 10²⁰ the gap H − a is 5.26·10⁶, which is 298 √H. Above x*, a > H, and the gap grows: 2.5·10¹⁰ at 10³¹, 1.1·10¹⁶ at 10⁴⁰. With π_q = H + noise of size √H (step 3), |a − H| < 10√H only on [3.9242·10³⁰, 3.9524·10³⁰], and < √H only on [3.9369·10³⁰, 3.9397·10³⁰]. Hence:

- for 10²⁰ ≤ x ≤ 3.92·10³⁰: √(2x)/ln x < π_q(x). At the published points this is a fact, not a model: π_q(10²⁸) = 2199894223892 exceeds √(2·10²⁸)/ln 10²⁸ by 6.4·10⁹;
- for every x ≥ 3.96·10³⁰: √(2x)/ln x > π_q(x);
- the first x > 10²⁰ with √(2x)/ln x > π_q(x) lies in that narrow window, most likely within 0.07 % of 3.9383·10³⁰.

What is not proved: all of this assumes the Hardy–Littlewood asymptotic with errors of the size seen in step 3. An unconditional proof would need π_q(x) < √(2x)/ln x, an upper bound within 3 % of the truth. Upper-bound sieves lose a constant factor here (the parity problem), and it is not even known that infinitely many primes n² + 1 exist. Locating the exact first x is also out of reach: π_q(4·10³⁰) needs every n up to 2·10¹⁵.

## Verify it yourself

[code/p454_count.py](code/p454_count.py) counts the primes n² + 1 exactly (`p454_count.py 100000000`, about 10 s). [code/p454_model.py](code/p454_model.py) computes C from the accelerated product, the residual table, the three crossover points, x*, the noise windows and the monotonicity of a/H. A minimal check of the crossing:

```python
from mpmath import mp, mpf, li, sqrt, log, exp, findroot
mp.dps = 30
C = mpf('1.3728134628182460091')
H = lambda x: C / 2 * (li(sqrt(x)) - li(sqrt(2)))
a = lambda x: sqrt(2 * x) / log(x)
L = findroot(lambda L: a(exp(L)) - H(exp(L)), 70)
print('x* = %.6e' % exp(L))
assert 3.938e30 < exp(L) < 3.939e30
assert a(mpf(10)**20) < H(mpf(10)**20) and a(mpf(10)**31) > H(mpf(10)**31)
```
