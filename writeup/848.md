# Puzzle 848: p(0)ₙq is prime for n = 0, 1, 2, …, k

> **In short:** The table of least p + q with p(0)ₙq (p, n zeros, q) prime for n = 0..k stopped at k = 8. The method: (1) for k ≥ 5 one prime must be 7, since ord₇(10) = 6; (2) sieve the other prime by small primes; (3) cover every value below 10¹¹. This gives k = 9: p = 95521311337, q = 7, minimal, with all ten numbers proven prime.

**Puzzle:** [primepuzzles.net](https://www.primepuzzles.net/puzzles/puzz_848.htm)

**Status:** beaten (Q1, k = 9) · minimal · proven primes

## The question

p(0)ₙq is p, then n zeros, then q. Q1: for each k, find the least p + q (p, q prime) such that p(0)ₙq is prime for every n = 0..k.

On the page:

- Jan van Delden gives the minima up to k = 7 (k = 7: p = 5113963, q = 7). He shows that for k ≥ 5 one of p, q must be 7: ord₇(10) = 6, so otherwise one of n = 0..5 gives a multiple of 7.
- Emmanuel Vantieghem gives k = 8: {7, 313292827}, sum 313292834. He notes that 17 caps the chain at n ≤ 14, since ord₁₇(10) = 16.

## How we found it

With one prime equal to 7 and the other called x (d digits), there are two cases:

```
case A (p = 7):  N_n = 7·10^(d+n) + x
case B (q = 7):  N_n = x·10^(n+1) + 7
```

Both are linear in x. For a small prime r, r | N_n is the single condition x ≡ −7·10^(d+n) (mod r) in case A, or x ≡ −7·10^(−(n+1)) (mod r) in case B. [`writeup/code/p848_search.c`](code/p848_search.c) crosses out these classes for n = 0..k, and x ≡ 0, for the first 400 primes r ∉ {2, 5, 7}. It then runs a probable-prime test (GMP) on x and N₀, N₁, … for the survivors. The same technique gave puzzle [882](882.md).

**The searched ranges.** A k = 9 chain is also a k = 8 chain, so the k = 8 search bounds where to start.

- k = 8 (sieving n = 0..8), x from 1000 to 4·10⁸, both cases: the first hit is Vantieghem's 313292827, in case A. So no k ≥ 8 chain has 1000 ≤ x < 313292827.
- k = 9 (sieving n = 0..9), x from 313292827 to 10¹¹, both cases: exactly one hit, x = 95521311337 in case B (13 minutes on 2 cores).
- The sieve cannot see primes x ≤ 2741, because each is one of its own sieving primes. A direct check of all x < 3000 finds no k = 9 chain.

Every x below 10¹¹ is covered in both cases, so 95521311344 is the least p + q for k = 9.

## The math

- **One of p, q is 7 for k ≥ 5** (van Delden, on the page). 10ⁿ runs through all six nonzero classes mod 7. If neither prime is 7, then p·10^(d+n) + q ≡ 0 (mod 7) for one n in every 6 consecutive values.
- **Proofs.** The ten numbers have 12 to 21 digits, above 2⁶⁴ from n = 8 on. Each one is proven prime by Lucas's test: with the full factorisation of N − 1, a base a whose order is exactly N − 1 shows that N is prime. Prime factors of N − 1 above 2⁶⁴ are proven the same way, recursively.

## Validation

[`writeup/code/p848_verify.py`](code/p848_verify.py) (under a second) checks:

- the ten primality proofs, and that n = 10 is composite;
- Vantieghem's k = 8 chain;
- the mod 7 argument on sample p, q;
- the small-x check below 3000.

```python
from sympy import isprime, factorint

def proven_prime(N):
    """Lucas (Pocklington) proof from the full factorisation of N - 1; recursive above 2^64."""
    if N < 2**64:
        return isprime(N)
    fac = factorint(N - 1)
    for q in fac:
        if not proven_prime(q):
            return False
    for a in range(2, 200):
        if pow(a, N - 1, N) != 1:
            return False
        if all(pow(a, (N - 1) // q, N) != 1 for q in fac):
            return True
    raise RuntimeError("no witness found")

p, q = 95521311337, 7
chain = [int(str(p) + "0" * n + str(q)) for n in range(10)]
assert isprime(p) and all(proven_prime(N) for N in chain)
assert not isprime(int(str(p) + "0" * 10 + str(q)))

assert all(isprime(int("7" + "0" * n + "313292827")) for n in range(9))   # k = 8 on the page

small = [x for x in range(2, 3000) if isprime(x) and
         (all(isprime(int("7" + "0" * n + str(x))) for n in range(10)) or
          all(isprime(int(str(x) + "0" * n + "7")) for n in range(10)))]
assert small == []
print("all checks pass")
```
