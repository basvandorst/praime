# Puzzle 1209: Unlucky primes in a row

> **In short:** The quadratic −3x² + 2799x + 22433 gives 34 different primes in a row (x = 0 to 33), and every one of them is "unlucky". The best valid run on the page has 30 different primes; a listed 45 turns out to contain five lucky numbers.

**Puzzle:** [primepuzzles.net](https://www.primepuzzles.net/puzzles/puzz_1209.htm)

**Status:** beaten (Q2) · proven primes

## The question

**Lucky numbers** come from a sieve. Write 1, 3, 5, 7, 9, … (the odd numbers). The second number is 3, so cross out every 3rd number left. The next survivor is 7, so cross out every 7th number left, and so on. What survives forever is lucky (1, 3, 7, 9, 13, 15, 21, …); everything crossed out is unlucky.

Davide Rotondo's function F(n) = 1.5n² + 16.1 (rounded) gives 61 values for n = −30 … 30, all unlucky primes, but only 30 of them are different (the function is symmetric and F(0) = F(1) = 17). Question 2 asks for a better polynomial giving more consecutive primes that are all lucky or all unlucky.

## Current record vs ours

| | Polynomial | Consecutive distinct unlucky primes |
|---|---|---|
| On the page (D. Rotondo) | ⌈1.5n² + 16.1⌉ / ⌊1.5n² + 16.1⌋ | 30 different (61 values with repeats) |
| On the page (G. Kalogeropoulos, 2025) | \|36n² − 810n + 2753\|, n = 0 … 44 | 45 claimed, but 5 are lucky: really 26 |
| **Ours** | −3x² + 2799x + 22433, x = 0 … 33 | **34** |

## How we found it

Kalogeropoulos explains on the page why Rotondo's values are always unlucky: the **second** step of the lucky sieve removes exactly the numbers that leave remainder 5 when divided by 6. So any number ≡ 5 (mod 6) is unlucky, and Rotondo's function always gives such numbers.

We turned this around. If we only look at polynomials whose values are **always** ≡ 5 (mod 6), every prime they produce is automatically unlucky, and we only need a long run of distinct primes. We searched exactly that family (values written as 6·Q(x) + 5) and found a run of 34.

Checking the 45-prime entry against the actual sieve shows why it fails. For n = 11 … 18 the value 36n² − 810n + 2753 is negative, and taking the absolute value turns "5 mod 6" into "1 mod 6", which is no longer protected. Five of those values (1801, 1693, 991, 613, 163) are lucky numbers.

## The math

The second sieve step removes every third odd number, the ones at positions 3, 6, 9, …:

```
odd numbers: 2i − 1,   removed at i = 3k   →   2·3k − 1 = 6k − 1 ≡ 5 (mod 6)
```

Our polynomial stays in that class:

```
P(x) = −3x² + 2799x + 22433
mod 6:   −3x² + 3x + 5 = −3·x(x − 1) + 5 ≡ 5,   since x(x − 1) is always even
```

## Verify it yourself

This script runs the lucky-number sieve, then checks that all 34 values are distinct primes, all unlucky. It also checks the five lucky values in the listed 45-prime entry.

```python
import numpy as np
from sympy import isprime

def lucky_numbers(limit):
    a = np.arange(1, limit, 2)              # start with the odd numbers
    i = 1
    while i < len(a) and a[i] <= len(a):
        step = a[i]                          # next survivor sets the step
        a = np.delete(a, np.arange(step - 1, len(a), step))   # remove every step-th survivor
        i += 1
    return set(a.tolist())

lucky = lucky_numbers(200_000)
assert sorted(lucky)[:8] == [1, 3, 7, 9, 13, 15, 21, 25]     # the sieve is right

P = lambda x: -3*x*x + 2799*x + 22433
vals = [P(x) for x in range(34)]
assert all(isprime(v) for v in vals) and len(set(vals)) == 34   # 34 different primes
assert all(v % 6 == 5 for v in vals)                             # all 5 mod 6 ...
assert not any(v in lucky for v in vals)                         # ... so none is lucky
assert not isprime(P(-1)) and not isprime(P(34))                 # the run is exactly 34

K = lambda n: abs(36*n*n - 810*n + 2753)
assert sorted(K(n) for n in range(45) if K(n) in lucky) == [163, 613, 991, 1693, 1801]

print("34 consecutive distinct unlucky primes")
```
