# Puzzle 418: Honaker's ratio

> **In short:** Honaker's ratio a(n) = (p_(n+1) + … + p_(2n)) / (p_1 + … + p_n) tends to 3, as the page shows. Its two open questions were whether it can drop below 3 again and whether it can equal 4. Neither happens: **3 < a(n) < 4 for every n ≥ 10** (and a(n) > 3 already from n = 3). So **a(n) is never an integer**, which answers Q1 completely. The proof is a direct check up to n = 1.07·10⁷, plus Dusart's explicit bounds for the n-th prime beyond that. The margin above 3 is about 2.77/ln n, while the bounds lose only about 0.2/ln n.

**Puzzle:** [primepuzzles.net](https://www.primepuzzles.net/puzzles/puzz_418.htm)

**Status:** answered (Q1 and the page's two open questions) · proof: exact check for n ≤ 1.07·10⁷ plus explicit prime bounds (Dusart 1999)

## The question

G. L. Honaker, Jr. looks at 3/2, (5 + 7)/(2 + 3), (7 + 11 + 13)/(2 + 3 + 5), … Q1: is a term ever an integer? Q2: does the ratio converge, and can it drop below e?

On the page, several contributors showed with Bach and Shallit's asymptotic for prime sums that a(n) → 3 (Q2). Patrick Capelle showed by parity that a(n) is never an odd integer, and listed the first terms: a(9) = 401/100 is the only one above 4. Dan Dima proved a(n) > 2 and suggested a(n) = 3 + 4 ln 2/ln n + o(1/ln n). The page closes with: "Open questions: Can the ratio be less than 3 again? Can the ratio be 4 sometime?"

## The math

Write S(n) = p_1 + … + p_n and T(n) = p_(n+1) + … + p_(2n), so a(n) = T(n)/S(n).

| # | Claim | Why | Validated |
|---|---|---|---|
| 1 | for n ≤ 9 the values are 3/2, 12/5, 31/10, 60/17, 101/28, 156/41, 223/58, 304/77, 401/100, none an integer | direct | exact |
| 2 | 3S(n) < T(n) for 3 ≤ n ≤ 10668163, and T(n) < 4S(n) for 10 ≤ n ≤ 10668163 | direct (exact 64-bit sums of the primes below 4·10⁸) | exact |
| 3 | k(ln k + ln ln k − 1) < p_k for k ≥ 2, and p_k < k(ln k + ln ln k − 0.9484) for k ≥ 39017 | Dusart (1999) | theorem |
| 4 | T(n) ≥ n²(1.5 ln n + 1.5 ln ln n + 2 ln 2 − 2.25) | claim 3 with ln ln k ≥ ln ln n on (n, 2n], and Σ_(k=n+1)^(2n) f(k) ≥ ∫_n^(2n) f for increasing f | algebra |
| 5 | S(n) ≤ S(39016) + (n + 1)²(ln(n + 1)/2 − 1/4 + (ln ln n − 0.9484)/2), with S(39016) = 8694566427 | claim 3 with ln ln k ≤ ln ln n, and Σ_(k=m)^n f(k) ≤ ∫_m^(n+1) f | algebra |
| 6 | for n ≥ 10⁷: T(n) − 3S(n) ≥ 1.3089 n² − 4.5 n(ln n + ln ln n) − 1.5 n − 3·S(39016) > 0 | claims 4–5; use ln(n + 1) ≤ ln n + 1/n; the n² coefficient is 2 ln 2 − 1.5 + 1.4226 = 1.3089 | evaluated, and the bound grows with n |
| 7 | for n ≥ 10⁷: 4S(n) − T(n) > 0, with margin about n²(0.5 ln n − 1.5 ln ln 2n + 2.5) | the same method with the bounds swapped (ln ln k ≥ ln ln 39017 = 2.358 for S) | evaluated on a grid up to 10¹⁵⁰; the margin grows with n |

Claims 1, 2, 6 and 7 together give 3 < a(n) < 4 for all n ≥ 10. Capelle's parity argument already excludes 3; here 3 is excluded because a(n) > 3 strictly. So no term is an integer.

**Why the margins are comfortable.** Asymptotically a(n) = 3 + 4 ln 2/ln n + O(1/ln² n). The data agree: a(10⁵) = 3.2423 against 3.2408, and a(10⁷) = 3.1694 against 3.1720. Dusart's two bounds differ by 0.0516·k. That shifts S and T by about 0.05/ln n relative, worth at most about 0.2/ln n on the ratio, against a margin of 2.77/ln n. That is why a plain integral comparison suffices above 10⁷. Below 10⁷ the closest approach to 3 is a(3) = 3.1; for large n it is a(10668163) = 3.1687.
