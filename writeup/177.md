# Puzzle 177: Primes in a square

> **In short:** Place 1 … n² in an n × n square so that horizontal and vertical neighbours add to primes; the page had squares for n = 4 … 80 but no strategy and no reason why n = 3 fails. (1) n = 3: the centre would need a prime sum with each of 2, 4, 6, 8, and no odd number up to 9 has that. (2) Strategy: odd numbers on one colour of a chessboard and even numbers on the other, then a min-conflicts swap search; it builds every n from 4 to 20 within seconds.

**Puzzle:** [primepuzzles.net](https://www.primepuzzles.net/puzzles/puzz_177.htm)

## The math

**Parity (proved).** A prime sum of two numbers ≥ 1 + 2 is odd, so neighbours have different parity: the parities form a chessboard pattern. For odd n the cells with i + j even number (n² + 1)/2, which is the number of odd values in 1 … n², so the odd numbers are forced onto those cells; for even n both colour classes have n²/2 cells and either choice works.

**n = 3 (proved).** The cells with i + j even are the four corners and the centre; they hold the odd numbers 1, 3, 5, 7, 9, and the four edge cells hold 2, 4, 6, 8. The centre is adjacent to all four edge cells, so its value c must satisfy c + 2, c + 4, c + 6, c + 8 all prime. Among odd c ≤ 9: c + 2 prime excludes 7; c + 4 prime excludes 5; c + 6 prime excludes 3 and 9; c + 8 prime excludes 1 and 7. Nothing remains. (Equivalently: the odd partners of 2, 4, 6, 8 are {1,3,5,9}, {1,3,7,9}, {1,5,7}, {3,5,9}; their intersection is empty.) The script also tests all 9! = 362880 arrangements: none works.

**Strategy (construction, checked).** Start from a random placement of the odd numbers on the black cells and the even numbers on the white cells. Repeat: pick a cell on an edge with composite sum, try swapping it with up to 150 random cells of the same colour, and perform the swap that reduces the number of composite-sum edges most; if no swap helps, make a random swap. After 60n² moves without success restart with a new random start. Every number has about n²/ln(n²) prime-sum partners, so conflicts are easy to repair, and the search converged on the first or second start for every n ≤ 20. The CP-SAT model (900 integer variables, all different, one sum variable with a prime domain per edge) solves n = 6 in 0.7 s and n = 10 in 9 s but gives no answer for n = 20 in 600 s, so the local search is the better strategy.
