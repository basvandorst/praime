# Puzzle 694, Q2: can 1(3)ₙ and 5(3)ₙ both be prime? (attempt)

> **In short:** A = 1(3)ₙ = (4·10ⁿ − 1)/3 and B = 5(3)ₙ = (16·10ⁿ − 1)/3 = 4A + 1. For even n both are composite, because each factors as a difference of two squares. For odd n no covering set of small primes exists: primes up to 2·10⁵ with ord_p(10) ≤ 2000 leave about 14 % of the odd residues uncovered. So a proof of "never" cannot come from small divisors. Heuristically the chance that both are prime is about c/n², so the expected number of odd n > 22002 (beyond Vantieghem's search) is about 10⁻⁵·c. Very likely there are none, but this is not proved.

**Puzzle:** [primepuzzles.net](https://www.primepuzzles.net/puzzles/puzz_694.htm)

**Status:** open · even n proved impossible; odd n: no covering set, heuristically none

## Even n

For n = 2h, (4·10ⁿ − 1)/3 = (2·10^h − 1)(2·10^h + 1)/3 and (16·10ⁿ − 1)/3 = (4·10^h − 1)(4·10^h + 1)/3. Both factors are larger than 3, so A and B are composite. This is the reason behind Vantieghem's "n must be odd".

## Odd n

A prime p ≠ 2, 3, 5 divides A when 10ⁿ ≡ 4⁻¹ (mod p), and divides B when 10ⁿ ≡ 16⁻¹ (mod p). So each p rules out a few residues of n mod ord_p(10).

`results/code/p694_cover.py` collects these residues for all primes below 2·10⁵ with ord_p(10) ≤ 2000 and tests moduli L up to 55440. A share of the residues always stays uncovered: 23 % for L = 30, 14 % for L = 55440 (for example n ≡ 15, 23, 29). The residue n ≡ 0 (mod L) can never be covered by such primes, because then A ≡ 1 and B ≡ 5 (mod p).

A proof would need a different kind of argument, for example an algebraic or Aurifeuillian factorisation that works for odd n. We found none.
