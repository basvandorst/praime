# Puzzle 957: Big primes from the digits 1 to 9 in order

> **In short:** Using the digits 1 to 9 (or 1 to 0, 9 to 1, 9 to 0) once each and in order, with + − × / and powers, we wrote primes of 1685 to 2989 digits. The largest on the page had 489 to 753 digits, but the follow-up puzzle 981 (2019) has larger titanic ones for two types: Simon Cavegn's 10930 digits (type a) and 7941 digits (type c), and Metin Sariyar's 1626 (type b) and 1177 (type d). So ours beat the record only for types b (1685 digits) and d (2023 digits). The trick was simply to aim for the size where there are enough candidate expressions to expect a prime, but each test is still fast.

**Puzzle:** [primepuzzles.net](https://www.primepuzzles.net/puzzles/puzz_957.htm)

**Status:** beaten (types b and d; types a and c are beaten by Cavegn on puzzle 981) · PRP (probable primes)

## The question

Write large primes as arithmetic expressions that use each digit exactly once, in a fixed order, with only + − × / ^ and parentheses (neighbouring digits may be glued together, like 89 or 890). Four types:

- (a) 1 2 3 4 5 6 7 8 9
- (b) 1 2 3 4 5 6 7 8 9 0
- (c) 9 8 7 6 5 4 3 2 1
- (d) 9 8 7 6 5 4 3 2 1 0

## Current record vs ours

| Type | Current record (P. Cleary, 2019) | Digits | **Ours** | **Digits** |
|---|---|---|---|---|
| (a) | `1+2*3^4^5-67-8-9` | 489 | `1-2+3*(4*5^6)^(7*89)` | **2989** |
| (b) | `-123^4-5+6+7^890` | 753 | `-(1+2)+34^(5*6*7+890)` | **1685** |
| (c) | `9+8^765+43*2*1` | 691 | `-9+8*7^(6*54*3^2)*1` | **2466** |
| (d) | `9+8^765-4+3^2*10` | 691 | `-9+8*76^(54-3+2^10)` | **2023** |

## How we found it

The size of the result is set by one power, BASE^EXPONENT, built from a run of neighbouring digits. The remaining digits form a small number added or subtracted, which decides whether the result can be prime at all.

Two things pull against each other. A random number with D digits is prime with probability about 1/(2.3·D), so bigger means rarer. And a primality test on D digits gets slower as D grows. The earlier record holder stopped around 500 to 750 digits. We counted how many different legal expressions exist in each size range and how long a test takes, and found that the range of about 2000 to 3000 digits still has enough candidates to expect a prime while each test takes well under a second.

So we generated all expressions of the shape (small part) ± A·BASE^EXP ± (small part) in that range, threw away those divisible by small primes (many are automatically divisible by 3 or by the base), and tested the rest.

## The math

For an expression with value N of D digits that is odd and not divisible by 3 or 5, the chance of being prime is roughly

```
P(prime) ≈ (2 · 3/2 · 5/4) / ln(N) = 3.75 / (2.303 · D)
```

so about 1 in 860 at D = 1400 and 1 in 1840 at D = 3000. Sieving out every candidate with a prime factor below 10⁶ raises the odds for the survivors by a factor of about 6.6 (e^γ · ln 10⁶ / 3.75), so roughly 130 to 280 tests per prime are expected. The actual searches needed 311 to 789 tests per type.

## The numbers

```
(a)  1-2+3*(4*5^6)^(7*89)        = 3·(62500)^623 − 1          (2989 digits)
(b)  -(1+2)+34^(5*6*7+890)       = 34^1100 − 3                 (1685 digits)
(c)  -9+8*7^(6*54*3^2)*1         = 8·7^2916 − 9                (2466 digits)
(d)  -9+8*76^(54-3+2^10)         = 8·76^1075 − 9               (2023 digits)
```

Conventions as in the listed entries: ^ binds right to left (4^5^6 = 4^(5^6)), and a leading minus sign applies after powers. All four values pass strong probable-prime tests to bases 2, 3, 5 and 30 Miller-Rabin rounds: probable primes, not proven ones.

## Validation

This script evaluates each expression with exact integer arithmetic, checks the digits appear exactly once in the required order, and tests the value for primality.

```python
import re
import sys
import gmpy2

sys.set_int_max_str_digits(0)                           # allow printing numbers with thousands of digits

answers = {
    "123456789":  "1-2+3*(4*5^6)^(7*89)",
    "1234567890": "-(1+2)+34^(5*6*7+890)",
    "987654321":  "-9+8*7^(6*54*3^2)*1",
    "9876543210": "-9+8*76^(54-3+2^10)",
}
listed = {"123456789": 489, "1234567890": 753, "987654321": 691, "9876543210": 691}

for order, expr in answers.items():
    assert re.sub(r"\D", "", expr) == order            # each digit once, in the required order
    N = eval(expr.replace("^", "**"))                   # Python's ** is right-associative, like ^
    assert gmpy2.is_strong_prp(N, 2) and gmpy2.is_strong_prp(N, 3)
    assert gmpy2.is_prime(N, 30)                        # probable prime
    digits = len(str(N))
    assert digits > listed[order]
    print(f"{order}: {expr}  ->  {digits}-digit probable prime (record {listed[order]})")
```
