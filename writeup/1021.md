# Puzzle 1021: Least prime p with p + p' + 1 (or p + p' + p'') squarefree with n prime factors

> **In short:** For consecutive primes p < p' < p'', the least p with p + p' + 1 (type A) or p + p' + p'' (type B) squarefree with n prime factors: tables to n = 20 agreed, a 100-term list differed at n = 16 and 20, and a table to n = 38 carried eight question marks. (1) The sum grows with p, so the least p comes from the least admissible sum x, an odd squarefree number with n prime factors that passes a one-line test on the primes nearest (x−1)/2 or x/3. (2) Generating these x in increasing order with a heap needs no bound. (3) The table is proven minimal to n = 100; the 100-term list is wrong at n = 16 and 20 (its primes are not consecutive).

**Puzzle:** [primepuzzles.net](https://www.primepuzzles.net/puzzles/puzz_1021.htm)

**Status:** answered (table of least p for both types, n = 1 … 100, proven primes, each entry proved minimal)

## The question

Paolo Lava: find the least prime p(k) such that p(k) + p(k+1) + 1 is squarefree with n prime factors, and the same for p(k) + p(k+1) + p(k+2); he gives n ≤ 6 (191 and 331 for n = 3) and asks for terms for n > 6 and whether such primes exist for every n. V. F. Izquierdo extended to n = 12, Paul Cleary to n = 20, Giorgos Kalogeropoulos sent 100 terms of each type (file), Oscar Volpatti a table to n = 38 obtained by enumerating odd squarefree x with prime factors ≤ 179, with a question mark where the least x might have been missed. Seiji Tomita confirmed n ≤ 9 below 10¹⁰.

## How we found it

Volpatti's reduction is the key: p + p' + 1 = x forces p ≤ (x−1)/2 < p', so p is the largest prime below (x−1)/2 + 1 and p' the next one; p + p' + p'' = x forces p < x/3 < p'' and leaves two candidate triples around x/3. Hence for every candidate x one test decides whether x is a sum of the required form. Since x is increasing in p, the least p corresponds to the least x. The candidates for n ≥ 3 are the odd squarefree numbers with exactly n prime factors (the only sums involving the prime 2 are 6 and 10). We generate them in increasing order with a heap over index tuples into the odd primes (each popped tuple spawns the tuples with one index raised), so the first x that passes is the least and no search bound is needed; the previous attempt with a bound (6 times the primorial) exhausted the memory near n = 40 ([`code/p1021_verify.py`](code/p1021_verify.py), 22 minutes for n ≤ 100, 10 seconds for n ≤ 44).

## The math

**Step 1 (proved). Reduction.** If x = p + p' + 1 with consecutive primes p < p', then 2p + 1 < x < 2p' + 1, so p < (x−1)/2 < p' … more precisely p ≤ (x−1)/2 < p' because x − 1 = p + p' is even only when p, p' are odd; thus p = prevprime((x−1)/2 + 1), p' = nextprime(p), and x is admissible iff p + p' + 1 = x. If x = p + p' + p'', then 3p < x < 3p'', so p < x/3 < p'' and the triple is one of (p₀, p₁, p₂) or (p₁, p₂, p₃) where p₁ = prevprime(⌊x/3⌋ + 1) and p₀, p₂, p₃ are its neighbours. For n ≥ 3 the sums with p = 2 (6 and 10) have two prime factors, so every admissible x is odd; it must be squarefree with n prime factors. Monotonicity: x is strictly increasing in k, so the least k is attained at the least admissible x.

**Step 2 (proved). Enumeration in order.** The odd squarefree numbers with n prime factors are the products over strictly increasing n-tuples of indices into the odd primes. From the tuple (i₁ < … < iₙ) the tuples obtained by raising one index by one (keeping strict increase) have larger products, and every tuple is reachable from the initial (0, 1, …, n−1) by such steps, so a heap keyed by the product, with a set of seen tuples, pops the products in non-decreasing order. The first popped x passing the type-A test gives the least p of type A, likewise for B.

**Step 3 (computed). The table.** [`data/p1021_table.txt`](data/p1021_table.txt) lists n, type, p, x and the prime factors of x for n = 1 … 100. Every p (and p', p'') is proven prime with PARI's isprime (APR-CL), consecutiveness is checked with nextprime, and x is factored. The number of candidates popped before the first hit stays small (between a dozen and a few thousand), so the whole table takes 22 minutes for n ≤ 100, 10 seconds for n ≤ 44. For n ≤ 20 the values agree with Cleary's; for n ≤ 38 with Volpatti's, so his eight question marks (n = 30, 31, 32, 34 … 38 of type A, 26, 30 … 38 of type B) are resolved in his favour. Kalogeropoulos's n = 16 (676225038401693428117) and n = 20 (18009308414688202025310904417) of type A are smaller than the true minima, but the next primes after his p are 676225038401693428147 and 18009308414688202025310904507, not the ones he added, so his sums are not of the required form; the same error (a second prime at twice the true gap) occurs in his type-A entries for n = 30, 38 and 62, which are also below the true minima. Of his 94 readable type-A terms 17 differ from ours (5 invalid, 12 above the minimum), of his 94 type-B terms 39 are above the minimum (none below).

**Step 4 (heuristic). Existence for every n.** The least admissible x for given n is near the product of the first n odd primes times a small factor; among the odd squarefree x with n factors in increasing order, each is a sum of the required form with probability about 2/ln x (the chance that the two primes around (x−1)/2 are at the right distance), so a hit comes after about (ln x)/2 candidates, in line with the counts observed (a few dozen to a few thousand), and the sequence should continue indefinitely, as the page's contributors expected.
