# Puzzle 1145: The covering set behind a Fermat-proof k

> **In short:** For k = 3·a² (35 digits) no prime k·2ⁿ + 1 divides a Fermat number; a smaller such k was asked, and the covering set was not given. The method: (1) covering primes need (−6/p) = 1; (2) twelve primes cover all odd n with period 360; (3) the page's a is least for that set. No covering set with a period below 1440 that divides 1440 gives a smaller a, within the product bounds searched; not a proof for all k.

**Puzzle:** [primepuzzles.net](https://www.primepuzzles.net/puzzles/puzz_1145.htm)

**Status:** first answer (Q1) · bounded search (no smaller k within the searched bounds; not a proof for all k)

**Update (2026-11-03):** the C program of the bounded search was not in the repository, so the search could not be repeated (pointed out by Carlos Rivera in his review for Puzzle 1288). It is now: [code/p1145_dfs.c](code/p1145_dfs.c), with [code/p1145_search.py](code/p1145_search.py), which builds its input and checks its output. The prime lists of the original run are replaced by complete ones, built from full factorisations, and the rerun reproduces every number below (see Validation).

## The question

For k = 3·a² with a = 153479820268467961, no prime of the form k·2ⁿ + 1 divides a Fermat number, because:

1. for even n, primes 3·a²·2²ᵐ + 1 can never divide a Fermat number, and
2. for odd n, k·2ⁿ + 1 is never prime: it has a **covering set**, a finite set of primes one of which always divides it.

Q1 asks for a smaller k with both properties that is not a Sierpiński number (so k·2ⁿ + 1 is prime for some n).

## How we found it

Write odd n = 2m + 1. Then k·2ⁿ + 1 = 6·a²·4ᵐ + 1. A prime p divides this for all m in one residue class mod the order of 4 modulo p, and only if a² ≡ −(6·4ʳ)⁻¹ (mod p) for the right r. That has a solution only when −6 is a square mod p, so only primes with (−6/p) = 1 can be used. This is a strong filter on which primes may appear in a covering set.

Given a set of primes, each way of assigning residue classes that covers every m (a "cover") fixes a² modulo every prime in the set, so a modulo their product, up to a choice of sign for each prime. The smallest a for the set is the minimum over all covers and all sign choices. For Wesolowski's set there are 34,560 covers, and the minimum is exactly his a. So his number is not a lucky find but the optimum for that set.

A depth-first search in C ([code/p1145_dfs.c](code/p1145_dfs.c)) then builds every cover of period N from the admissible primes whose order of 4 divides N, keeps the prime sets whose product stays below a bound B, and computes the least a of each set it finds. It assigns a residue class to one uncovered m at a time (the m with the fewest candidates first), never uses the same prime twice, and prunes a branch when the primes still affordable under B cannot cover what is left (a fractional knapsack bound). The classes of 5 and 7 are fixed to 0, which loses nothing: every cover that uses 5 and 7 is a shift of one with those classes, and the 6 shifts are put back when a is computed.

The pool for period N is complete. ord_p(4) divides N exactly when p divides 4ᴺ − 1 = ∏ Φ_e(2) over e | 2N, so the pool is the set of admissible prime factors of those cyclotomic values. [data/p1145_cyclo.txt](data/p1145_cyclo.txt) holds the full factorisation of every Φ_e(2) that is needed (PARI `factor`, and factordb.com for Φ₁₄₄₀(2)); the script checks each line by multiplying it out and proving each factor prime. The program works with 64-bit primes, so the seven admissible factors above 2⁶⁴ (22 to 80 digits, orders 240 to 720) are left out. A cover using one of them would need all its other primes to multiply to less than 2.2·10⁶ to beat the page's product.

## Validation

This script checks the covering set for both values of a (every odd n up to 1441, two full periods, has a factor in the set), the condition (−6/p) = 1 for every prime used, the period 360, and that k·2ⁿ + 1 is a probable prime for the stated even n.

```python
from math import lcm
from gmpy2 import is_prime, mpz
from sympy import legendre_symbol, n_order

sets = {
    153479820268467961:  ([5, 7, 11, 31, 73, 97, 151, 241, 631, 673, 1321, 23311], 600),
    2102924150668420411: ([5, 7, 11, 31, 73, 97, 151, 241, 631, 673, 1321, 54001], 80),
}
for a, (cover, even_n) in sets.items():
    k = 3 * a * a
    assert a % 2 == 1 and a % 3 != 0                                 # k = 3a^2, a odd, not divisible by 3
    assert all(legendre_symbol(-6 % p, p) == 1 for p in cover)        # -6 is a square mod every p
    assert lcm(*(n_order(4, p) for p in cover)) == 360               # period 360 in m, so 720 in n
    uncovered = [n for n in range(1, 1442, 2) if all((k * pow(2, n, p) + 1) % p for p in cover)]
    assert uncovered == []                                           # every odd n has a factor in the set
    assert is_prime(mpz(k) * 2**even_n + 1, 25)                      # PRP: k is not a Sierpinski number
    print("a =", a, ": covering set verified, k*2^%d + 1 is a probable prime" % even_n)

assert 153479820268467961 < 2102924150668420411
```

### Repeating the search

[code/p1145_search.py](code/p1145_search.py) checks the factorisations in [data/p1145_cyclo.txt](data/p1145_cyclo.txt), builds the pool and the input for each period, runs [code/p1145_dfs.c](code/p1145_dfs.c) (in parts that split the tree, niced) and adds up its output per prime set. `all` asserts every row of the two tables in "How we found it". It needs `sympy` and `cypari2`.

```
gcc -O2 -o writeup/code/p1145_dfs writeup/code/p1145_dfs.c -lm
python3 writeup/code/p1145_search.py pool            # the pool of every period, under a second
python3 writeup/code/p1145_search.py run 360 1e29 4  # one period: N, bound, parts
python3 writeup/code/p1145_search.py all             # every run, then the assertions
```

On one core of a small server (2026-11-03): under 6 seconds for each period up to 288 and for 480, 2 minutes for 360, 8 minutes for 720.
