# Puzzle 553: A sum of consecutive numbers equal to a product of consecutive primes

> **In short:** We found two consecutive primes p and q (1060 digits) such that p + (p+1) + … + q equals the product of the 333 consecutive primes 523, 541, …, 3001. The longest product known before had 319 primes.

**Puzzle:** [primepuzzles.net](https://www.primepuzzles.net/puzzles/puzz_553.htm)

**Status:** beaten · PRP (probable primes)

## The question

Add up all whole numbers from one prime to the next prime. Sometimes the total is a product of consecutive primes:

```
19 + 20 + 21 + 22 + 23 = 105 = 3 · 5 · 7
```

The puzzle asks for larger such intervals; the record is the one whose product uses the most consecutive primes.

## Current record vs ours

| | Product of consecutive primes | Number of primes | Size of p |
|---|---|---|---|
| Current record (G. Resta) | 349 · … · 2677 | 319 | 988 digits |
| **Ours** | 523 · … · 3001 | **333** | 1060 digits |

## How we found it

We started by re-checking the 18 solutions already on the page and looking for what they have in common. It turned out that the gap k = q − p is far from random:

- k + 1 is always a product of primes **from the run**,
- k/2 never contains a prime from the run,
- every other prime of the run then divides p + k/2, which fixes p almost completely.

That turns the hunt into a short list: for each run of consecutive primes, only a few gaps k are allowed, and each gives one candidate p. We scored every (run, gap) pair by its chance of producing two consecutive primes, tried the best ones first, and checked that the scoring found Resta's known solutions. It then pointed to the run 523 … 3001 with gap 2592, which works.

## The math

The sum of the k + 1 numbers from p to q = p + k is

```
p + (p+1) + … + (p+k) = (k + 1)(2p + k) / 2 = (k + 1) · (p + k/2)
```

and must equal the product of the run of primes a, …, L (each prime once). Comparing both sides:

```
1. k + 1 must be a product of distinct primes from the run
2. k/2 shares no prime with the run           (otherwise that prime would appear twice)
3. p + k/2 = (product of the run) / (k + 1)   (this fixes p exactly)
```

Then the only luck needed is that p and q = p + k are prime and that nothing in between is prime. For ours:

```
run:   the 333 consecutive primes 523, 541, …, 3001
k = 2592,   k + 1 = 2593 (a prime in the run),   k/2 = 1296 = 2^4 · 3^4
p = (523 · 541 · … · 3001) / 2593 − 1296          (1060 digits)
```

## The numbers

p is in [data/553.txt](data/553.txt) and q = p + 2592. Both pass the BPSW test and 25 Miller-Rabin rounds (probable primes); every number strictly between them fails a Miller-Rabin test, so they really are consecutive.

## Verify it yourself

This script rebuilds p from the product of the run, checks the sum identity, and checks that p and q are consecutive (probable) primes. It takes about half a minute.

```python
import math
import gmpy2
from sympy import primerange

run = list(primerange(523, 3002))                  # 523, 541, ..., 3001
assert len(run) == 333

k = 2592
product = math.prod(run)
p = product // (k + 1) - k // 2                    # from (k+1)(p + k/2) = product
q = p + k

assert p == int(open("results/data/553.txt").read().split()[-1])   # same p as the data file
assert (k + 1) * (2 * p + k) // 2 == product      # p + (p+1) + ... + q equals the product
assert gmpy2.is_prime(p, 25) and gmpy2.is_prime(q, 25)              # both probable primes
assert not any(gmpy2.is_prime(p + i, 3) for i in range(1, k))       # no prime in between

print("333 consecutive primes multiply to the sum from p to q; p has", len(str(p)), "digits")
```

Run it from the repository root, so the relative path `results/data/553.txt` resolves.
